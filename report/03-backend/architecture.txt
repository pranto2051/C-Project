BACKEND ARCHITECTURE
====================

Framework: ASP.NET Core Web API (.NET 9.0)
Pattern: Clean Architecture (4 layers)
Solution: ECommerce.sln

===============================================================================
LAYER STRUCTURE
===============================================================================

┌─────────────────────────────────────────────────────────────┐
│                    ECommerce.API                            │
│                    (Presentation Layer)                      │
│                                                             │
│  - Controllers (6 controllers)                              │
│  - Middleware (ExceptionHandlingMiddleware)                  │
│  - Program.cs (DI, CORS, Swagger)                          │
│  - appsettings.json / appsettings.Development.json          │
└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                ECommerce.Application                        │
│                (Application Layer)                           │
│                                                             │

│  - DTOs (Request/Response models)                           │

└─────────────────────────┬───────────────────────────────────┘
                          │
                          ▼
┌─────────────────────────────────────────────────────────────┐
│                 ECommerce.Domain                            │
│                 (Domain Layer - Pure)                        │

└─────────────────────────────────────────────────────────────┘

===============================================================================
DEPENDENCY RULES
===============================================================================

- API → Application, Infrastructure
- Application → Domain
- Infrastructure → Domain
- Domain → Nothing (pure, no dependencies)

This ensures:
- Domain logic is testable without infrastructure
- Application logic is testable without API
- Infrastructure can be swapped (e.g., different database)
- Clean separation of concerns
