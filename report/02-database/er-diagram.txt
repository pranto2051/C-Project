RELATIONSHIP SUMMARY
====================

1. ADMINS — (standalone, no relationships to other auth tables)

2. DEALERS 1:N PRODUCTS
   - One dealer can have many products
   - Each product belongs to exactly one dealer

3. CATEGORIES 1:N PRODUCTS
   - One category can contain many products
   - Each product belongs to exactly one category

4. CATEGORIES self-referencing (ParentCategoryId)
   - A category can have a parent category
   - Enables subcategory hierarchy

5. PRODUCTS 1:N PRODUCT_IMAGES
   - One product can have many images
   - Each image belongs to exactly one product

6. CUSTOMERS 1:1 CARTS
   - Each customer has exactly one active cart
   - Cart is created on first add-to-cart

7. CARTS 1:N CART_ITEMS
   - One cart can contain many items
   - Each item belongs to exactly one cart

8. CART_ITEMS N:1 PRODUCTS
   - Each cart item references one product
   - A product can appear in many cart items

9. CUSTOMERS 1:N ORDERS
   - One customer can place many orders
   - Each order belongs to exactly one customer

10. ORDERS 1:N ORDER_ITEMS
    - One order can contain many items
    - Each item belongs to exactly one order

11. ORDER_ITEMS N:1 PRODUCTS
    - Each order item references one product
    - A product can appear in many order items

12. ORDER_ITEMS N:1 DEALERS
    - Each order item references one dealer (denormalized)
    - Enables dealer-specific order queries
